# Автоматизированная система учёта средств измерений (СИ)

Полнофункциональная веб-система для метрологических служб и складов измерительной техники с поддержкой аппаратного терминала на базе микроконтроллера **ESP32-S3** и лазерного сканера **Waveshare Barcode Scanner Module (E)** по протоколу UDP.

---

## 📋 Основные возможности

1. **Метрологический контроль и бизнес-правила:**
   - Строгая автоматическая блокировка выдачи приборов с просроченным свидетельством о поверке (в соответствии с 102-ФЗ «Об обеспечении единства измерений»).
   - Проверка наличия права получения СИ у сотрудников (с возможностью оперативной блокировки/разблокировки).
   - Защита от повторной выдачи прибора, находящегося на руках, в поверке или ремонте.
   - Фиксация фактического лица, возвращающего прибор (может отличаться от получателя).

2. **Интеграция с аппаратным терминалом ESP32-S3 (UDP 5005):**
   - Приём пакетов сканирования `SCAN:<код>` и признака жизни `HEARTBEAT:<rssi>`.
   - Поддержка «сырых» кодов штрихкодов без префиксов.
   - Аппаратная защита от дребезга сканера: автоматическая дедупликация повторных сканов за интервал < 350 мс.
   - Мониторинг статуса связи в реальном времени (онлайн / оффлайн при задержке более 6 с, замер уровня сигнала Wi-Fi в дБм).
   - Встроенный интерактивный эмулятор терминала прямо в веб-интерфейсе для отладки без физического «железа».

3. **Реестр приборов и маркировка:**
   - Полноценный каталог СИ: наименование, модель, заводской номер, инвентарный номер, место хранения на складе, дата следующей поверки, тех. характеристики.
   - Генерация и печать QR-этикеток термотрансферных форматов (58×40 мм и 40×30 мм) с высоким контрастом для мгновенного считывания сканером.
   - Экспорт в CSV.

4. **Инвентаризация парка СИ:**
   - Открытие сессий инвентаризации по зонам (стеллаж, полка).
   - Пакетное поточное сканирование приборов подряд.
   - Дифференциальный отчёт в реальном времени: «В наличии (на месте)», «Недостача (отсутствует)», «Пересортица (лишнее)».
   - Закрытие сессии с фиксацией акта сличительной ведомости.

5. **Неизменяемый журнал движений (Append-Only):**
   - Юридически значимый аудит всех операций (выдача, возврат, отправка в ЦСМ, ремонт, списание).
   - Запрет на модификацию и удаление существующих записей в БД.

6. **Аналитические отчёты и приёмочные тесты:**
   - График поверки на 30/60/90 дней с визуализацией на графиках Recharts.
   - Список задолженностей и просроченных возвратов.
   - Встроенный автоматический тестовый стенд (ПСИ), покрывающий 8 ключевых сценариев бизнес-правил.

## 🚀 Запуск и сборка

### Разработка (Development)
```bash
# Установка зависимостей
npm install

# Запуск сервера разработки (Express + Vite HMR + UDP-сокет на порту 5005)
npm run dev
```
Приложение доступно по адресу: `http://localhost:3000`.
UDP-сервер слушает порт: `5005` (приём пакетов терминала).

### Промышленный запуск (Production)
```bash
# Сборка фронтенда и бандлинг сервера в dist/server.cjs
npm run build

# Запуск скомпилированного сервера
npm start
```

## 🔌 Подключение терминала ESP32-S3

### 1. Аппаратная схема подключения
- **Микроконтроллер:** ESP32-S3-WROOM-1 (или аналогичный модуль с Wi-Fi).
- **Модуль сканера:** Waveshare Barcode Scanner Module (E).
- **Интерфейс связи:** Аппаратный UART1.

| Waveshare Scanner Pin | ESP32-S3 Pin | Назначение |
|---|---|---|
| **VCC** | 3.3V или 5V | Питание модуля |
| **GND** | GND | Общий провод |
| **TXD** | GPIO 18 (RX1) | Передача данных от сканера к ESP32 |
| **RXD** | GPIO 17 (TX1) | Команды настройки от ESP32 |

### 2. Формат сетевых пакетов (UDP Port 5005)
1. **Скан штрихкода:**
   ```text
   SCAN:DEV:00101
   SCAN:CARD:0004928192
   ```
   *(Также поддерживается отправка кода без префикса `SCAN:`)*
2. **Heartbeat (каждые 2 секунды):**
   ```text
   HEARTBEAT:-62
   ```
   где `-62` — уровень сигнала Wi-Fi RSSI в дБм.

### 3. Пример прошивки для ESP32 (Arduino IDE / PlatformIO)
```cpp
#include <WiFi.h>
#include <WiFiUdp.h>

const char* ssid     = "WAREHOUSE_WIFI";
const char* password = "WarehouseSecretKey";
const char* serverIp = "192.168.1.100"; // IP-адрес сервера учёта СИ
const int   udpPort  = 5005;

WiFiUDP udp;
HardwareSerial ScannerSerial(1); // UART1 (GPIO 18=RX, GPIO 17=TX)
unsigned long lastHeartbeat = 0;

void setup() {
  Serial.begin(115200);
  ScannerSerial.begin(115200, SERIAL_8N1, 18, 17);

  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWiFi connected! IP: " + WiFi.localIP().toString());
}

void loop() {
  // Отправка HEARTBEAT каждые 2 с
  if (millis() - lastHeartbeat >= 2000) {
    lastHeartbeat = millis();
    long rssi = WiFi.RSSI();
    String hbMsg = "HEARTBEAT:" + String(rssi);
    udp.beginPacket(serverIp, udpPort);
    udp.write((const uint8_t*)hbMsg.c_str(), hbMsg.length());
    udp.endPacket();
  }

  // Считывание данных сканера
  if (ScannerSerial.available()) {
    String barcode = ScannerSerial.readStringUntil('\r');
    barcode.trim();
    if (barcode.length() > 0) {
      String scanMsg = "SCAN:" + barcode;
      udp.beginPacket(serverIp, udpPort);
      udp.write((const uint8_t*)scanMsg.c_str(), scanMsg.length());
      udp.endPacket();
      Serial.println("Sent: " + scanMsg);
    }
  }
}
```

## 💾 Резервное копирование и восстановление

1. **Экспорт дампа:**
   - В интерфейсе: вкладка **«Настройки» → «Выгрузить дамп базы (JSON)»**
   - По API: `GET /api/database/backup` (скачивает полный снимок таблиц в формате JSON).

2. **Восстановление:**
   - В интерфейсе: вкладка **«Настройки» → «Загрузить резервную копию»**
   - По API: `POST /api/database/restore` с телом JSON-дампа.

3. **Сброс к исходным демо-данным:**
   - Кнопка **«Сброс к эталонным демо-данным»** на вкладке «Настройки» восстанавливает парки приборов, сотрудников и журнал к начальному состоянию.

4. **Схема базы данных:**
   Файл `schema.sql` содержит DDL-схему для развёртывания в реляционных СУБД (SQLite / PostgreSQL).

## ✅ Программа приёмо-сдаточных испытаний (ПСИ)

Система содержит встроенный автоматический стенд тестирования (`/api/tests/run` и вкладка «Тесты приёмки»):
1. **Успешная выдача прибора:** статус переходит в `issued`, привязывается держатель и плановый срок возврата.
2. **Блокировка выдачи просроченного прибора:** отклонение с кодом ошибки `VERIFICATION_EXPIRED`.
3. **Блокировка выдачи занятого прибора:** отклонение с кодом ошибки `DEVICE_NOT_AVAILABLE`.
4. **Блокировка сотрудника без прав:** отклонение с кодом ошибки `EMPLOYEE_CANNOT_BORROW`.
5. **Успешный возврат прибора:** статус переходит в `in_stock`, очищается держатель.
6. **Возврат прибора другим сотрудником:** корректная фиксация фактического сдавшего в журнале.
7. **Неизменяемость журнала:** движения пишутся строго в режиме append-only.
8. **Мониторинг терминала:** переход в оффлайн при превышении таймаута сердцебиения (6 с).
